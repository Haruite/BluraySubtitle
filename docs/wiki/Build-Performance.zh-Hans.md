## Windows 安装脚本

三次实测的源码均基于提交 `c83b40c0238dfed5ddf50e830a2de1b3239bf757`（`fix(setup): fall back when GitHub release API fails`）。基线使用优化前的工作区快照，优化后冷跑和缓存恢复使用优化后的快照。两份快照均包含测试时尚未提交的改动。

2026 年 11 月 9 日的测试使用 x64 Windows 11 虚拟机，配置为 Intel Core i5-13600KF、20 个逻辑处理器、24 GiB 内存、Visual Studio Enterprise 2026、CMake 4.4.5 和 Ninja 1.13.2。每列为一次 `-Mode Build` 实测，计时从脚本进程启动到清理临时文件完成。

基线与优化后冷跑均从空的构建及 pip 缓存开始，保留 MSYS2 下载缓存。基线预装 Python 3.12.10，构建使用 Python 3.15.2。缓存恢复复测清空已安装的项目工具和 VapourSynth 的 Python 加载入口，保留 Python、已安装的 MSYS2 依赖和构建缓存。9 个构建缓存归档合计约 274 MiB。

## Docker 镜像构建

## Linux 安装脚本（WSL 2）

2026 年 11 月 9 日的测试使用提交 `c83b40c0238dfed5ddf50e830a2de1b3239bf757` 中的 `setup_linux_environment.sh`。Ubuntu 26.04.1 LTS 与 Ubuntu 22.04.5 LTS 运行在同一台 x86-64 WSL 2 主机上，配置为 Intel Core i5-13600KF、20 个逻辑处理器和 62.79 GiB 的 WSL 可见内存，内核为 `6.18.54.1-microsoft-standard-WSL2`。

两个发行版在首次运行前均已将 Ubuntu APT 源指向清华大学镜像（HTTPS），并完成 `apt update` 和 `apt upgrade`。各次运行通过 WSL 的 root 会话串行、非交互执行。26.04 的 `/tmp` 挂载为 tmpfs，22.04 的 `/tmp` 位于 ext4 文件系统，两者的 `/var/tmp` 均位于 ext4 文件系统。

22.04 首次运行在配置 mpv 所用的 libplacebo 时以退出码 `1` 结束。root 会话已将 Meson 1.12.1 安装到 Python 用户站点。构建设置 `PYTHONNOUSERSITE=1` 后读到系统自带的 Meson 0.61.2，而 libplacebo 要求至少 1.3.0。随后禁用用户站点并安装系统级 Meson 1.12.1。复跑复用了已经安装的系统依赖、Shaderc、MKVToolNix、VapourSynth、libdovi 和 dav1d。26.04 首次运行和 22.04 复跑均通过安装校验，退出码为 `0`。
