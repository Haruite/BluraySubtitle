# 蓝光原盘结构

[English](Blu-ray-Disc-Structure.md) | 简体中文

本页从蓝光目录树一直讲到传输流数据包，重点介绍 BluraySubtitle 实际读取的结构，以及决定播放列表真正播放内容的时间规则。

## 原盘根目录

电影蓝光通常会在文件系统根目录呈现两个目录：

```text
BDROM/
├── BDMV/
└── CERTIFICATE/
```

`CERTIFICATE` 与原盘／应用认证有关，不属于本文描述的媒体提取路径。`BDMV` 保存播放应用和音视频内容。

商业原盘还可能包含加密或保护相关数据。AACS 和 BD+ 工作在播放列表与容器层的下方或旁侧。BluraySubtitle 要求操作系统已经能够读取这些文件；它本身不是 AACS 或 BD+ 解密器。

## BDMV 目录

典型目录树如下：

```text
BDMV/
├── index.bdmv
├── MovieObject.bdmv
├── PLAYLIST/
│   ├── 00000.mpls
│   └── ...
├── CLIPINF/
│   ├── 00000.clpi
│   └── ...
├── STREAM/
│   ├── 00000.m2ts
│   └── ...
├── BACKUP/
│   ├── index.bdmv
│   ├── MovieObject.bdmv
│   ├── PLAYLIST/
│   └── CLIPINF/
├── AUXDATA/          （可选）
├── META/             （可选）
├── BDJO/             （BD-J，可选）
└── JAR/              （BD-J，可选）
```

重要关系如下：

```text
index.bdmv
    └─ 标题入口
       └─ MovieObject.bdmv 或 BD-J 对象
          └─ 启动播放列表
             └─ PLAYLIST/xxxxx.mpls
                ├─ 选择一个或多个片段时间窗口
                │  ├─ CLIPINF/yyyyy.clpi
                │  └─ STREAM/yyyyy.m2ts
                └─ 定义播放列表标记和流条目
```

### `index.bdmv`

索引表定义顶层标题入口、首次播放和菜单入口行为。标题会引用 HDMV Movie Object 或 BD-J 应用。

### `MovieObject.bdmv`

Movie Object 包含由 HDMV 虚拟机解释的导航命令。这些命令可以启动播放列表、在对象之间跳转、更新播放器寄存器并响应导航事件。

BluraySubtitle 不模拟完整导航应用。项目关心的是识别并处理编排好的播放列表与片段。

### `PLAYLIST`

每个 `xxxxx.mpls` 都是一个 **Movie PlayList**。它通过一个或多个片段时间区间定义有序的虚拟时间线，还可以包含流选择元数据、子路径、多角度引用和播放列表标记。

### `CLIPINF`

每个 `xxxxx.clpi` 描述相应的 `STREAM/xxxxx.m2ts`。CLPI 包含片段时钟、节目和流元数据，以及用于把呈现时间映射到传输流数据包位置的索引。

### `STREAM`

每个 `xxxxx.m2ts` 保存复用后的音视频和图形数据包。仅凭文件名无法判断它是正片、SP、菜单、静止画面、纯音频内容还是可重复使用的分支片段。

### `BACKUP`

重要导航和片段信息结构会在 `BACKUP` 下保存副本。体积巨大的 `STREAM` 目录不会重复保存。主元数据丢失或损坏时，软件可以查询备份副本。

### 可选内容

- `AUXDATA` 可以保存辅助音频和字体数据。
- `META` 可以保存 XML 元数据和图片。
- `BDJO` 与 `JAR` 用于 BD-J 应用。
- 交互式菜单图形通常作为 M2TS 内的流存在，而不是普通图片文件。

## 原盘中的特殊内容

原盘是一套播放应用，不只是电影文件的集合。很小或时长异常的流可能是菜单和导航所需资源，不能仅因“几乎没有时长”就判定无用。

### HDMV／BD-J 菜单与 IGS

蓝光主要有两种导航模型：

- **HDMV** 菜单使用 `MovieObject.bdmv` 中的命令以及图形／菜单流；
- **BD-J** 标题使用 `BDJO`／`JAR` 中的 Java 应用，并调用原盘媒体和图形资源。

一个 HDMV 菜单通常由多个平面合成：

1. 视频或静止画面背景；
2. **IGS**（Interactive Graphics Stream，stream type `0x91`），其中包含菜单 page、按钮组、对象位图、调色板和普通／选中／激活状态；
3. 决定按钮行为的导航命令。

因此 IGS 不是普通字幕，也不一定单独构成完整菜单画面。提取有代表性的按钮状态 PNG 便于检查和保留，但不能还原 HDMV 虚拟机、BD-J 应用、用户操作限制、菜单音效以及全部状态跳转。

BluraySubtitle 会把含 IGS 但不含视频的 M2TS 分类为 `igs_menu`。对于支持的 SP 输出，项目会根据调色板、对象和合成 segment 重建 page/state 图片。这里保留的是可检查图形，不是可交互原盘导航。

### 静止画面与单帧视频

菜单背景或画廊图片可能是真正的视频流，但解码后只有一帧。播放列表通过保持该帧来显示静止画面，而不必存储几秒或几分钟重复帧。因此，对应 M2TS 可能非常小，媒体时长也可能接近零，这并不表示文件损坏。

MPLS 的 `PlayItem` 还包含编排好的静止播放字段：

| `StillMode` | 含义 |
| ---: | --- |
| `0` | 普通播放，不保持静止 |
| `1` | 将最终呈现保持 `StillTime` 秒 |
| `2` | 无限保持，直到导航继续 |

物理单帧流与播放列表静止指令有关，但不是同一概念。只统计 M2TS 帧数，无法知道原盘播放器会让它停留多久；还必须结合 `StillMode`、`StillTime` 和导航行为。

扫描 SP 时，BluraySubtitle 会把很小的视频源——当前要求涉及的每个 M2TS 不超过 1 MiB——且每个源已知帧数不超过一帧的内容，分类为单帧或多片段静止内容。这里的体积检查是项目用于快速分类的保护条件，不是蓝光规范上限。无法确定帧数、纯音频或更大的流会进入其他分类路径。

### 其他非正片布局

原盘还可能包含：

| 布局 | 常见用途 | 保留时的注意事项 |
| --- | --- | --- |
| 纯音频 M2TS | 菜单音乐、评论或独立声音节目 | 不能强制要求视频轨 |
| 纯字幕或音频带字幕 M2TS | 辅助呈现流 | 根据所选轨道使用 `.mks`、`.mka` 或合适容器 |
| 未被任何 MPLS 引用的 M2TS | 遗留资源或由菜单直接访问的素材 | 只扫描播放列表会漏掉 |
| 多角度 PlayItem | 不同机位、字幕／演职员表或语言版本 | 同一 MPLS 区间可以引用备选片段 |
| 次要视频／音频与 SubPath | 画中画、评论、MVC dependent view | 不一定属于主线性流 |
| 无缝分支 | 多个剪辑版本共用片段 | 文件体积和文件名顺序不能确定最终标题 |

因此，BluraySubtitle 会列出有用的未引用 M2TS，并按轨道组成分类，而不是假定所有 SP 都是普通短视频。

## 播放原盘与确认 MPLS

播放 BDMV 目录有助于确认正片，但不同入口并不具有相同语义。

### PotPlayer 拖入原盘目录

在 Windows 中可以把 BDMV／原盘目录拖入 PotPlayer。这个入口通常接近自动标题选择，往往会选时长最长的 MPLS。它适合快速查看，但在剧集原盘、无缝分支版本、含重复片段的播放列表或刻意干扰最长标题判断的原盘中可能选错。

因此，拖入目录后的播放结果不能作为主 MPLS 的唯一证明；这个入口在本工作流中也没有提供完整原盘导航。应核对片段顺序、章节、语言和实际内容，再在 BluraySubtitle 中明确选择目标 MPLS。

### 使用 mpv 播放指定播放列表

mpv 的蓝光输入使用 URL 风格命令，不能把 `.mpls` 当普通媒体文件直接打开：

```powershell
mpv "bd://mpls/00001" --bluray-device="D:\Disc"
```

`00001` 对应 `BDMV/PLAYLIST/00001.mpls`，`--bluray-device` 指向包含 `BDMV` 的原盘根目录。普通 `bd://` 命令可能选择 `longest` 或 `first` 等默认标题；要验证具体播放列表，应使用 `bd://mpls/<编号>`。mpv 必须带 libbluray 支持，加密内容也必须已经能够读取。

BluraySubtitle 已把这条命令集成到播放列表／SP 的“播放”按钮。Windows 配置了 mpv 时，GUI 会传入准确的所选 MPLS 编号和原盘根目录，并可附加匹配外挂字幕用于预览。没有可用 mpv 时，Windows 会回退到操作系统文件关联，此时如何选择播放列表取决于关联播放器。

直接播放 MPLS 会有意绕过原盘顶层菜单导航。它用于核对指定播放列表，不是完整原盘应用模拟器。

## MPLS、M2TS 与 CLPI 如何协作

三者回答不同的问题：

| 结构 | 主要职责 |
| --- | --- |
| MPLS | 播放哪些片段、以什么顺序播放、每个片段播放哪个时间区间？ |
| CLPI | 某个 M2TS 片段具有怎样的时钟、节目和索引信息？ |
| M2TS | 实际复用后的视频、音频和图形数据包存放在哪里？ |

MPLS 的 `PlayItem` 包含一个五字符的 `ClipInformationFileName`。当其值为 `00042` 时，逻辑关系如下：

```text
PLAYLIST/xxxxx.mpls
  PlayItem.ClipInformationFileName = "00042"
                       │
                       ├── CLIPINF/00042.clpi
                       └── STREAM/00042.m2ts
```

MPLS 通常不嵌入视频或音频；M2TS 本身也不会说明某个标题应播放其中哪一部分；CLPI 则提供正确导航 M2TS 所需的时钟和流描述。

## MPLS 二进制结构

MPLS 以一个头部开始，包含：

- 四字节类型标识，通常为 `MPLS`；
- 四字节版本标识；
- `PlayListStartAddress`；
- `PlayListMarkStartAddress`；
- `ExtensionDataStartAddress`；
- 保留字节。

主要区域包括：

1. `AppInfoPlayList`；
2. `PlayList`，其中包含 `PlayItem` 和 `SubPath`；
3. `PlayListMark`；
4. 可选扩展数据。

这些地址都是相对于文件开头的字节偏移。解析器应使用地址和声明长度，不能假定可变长度区域必然紧邻排列。

### PlayList

播放列表区域包含：

- `NumberOfPlayItems`；
- `NumberOfSubPaths`；
- 有序的 `PlayItem` 列表；
- 有序的 `SubPath` 列表。

主要线性时间线来自 `PlayItem` 列表。子路径可以携带画中画等次要或同步内容。

### PlayItem

播放项包含：

| 字段 | 含义 |
| --- | --- |
| `ClipInformationFileName` | 五位片段标识 |
| `ClipCodecIdentifier` | 通常为 `M2TS` |
| `IsMultiAngle` | 后方是否存在其他角度片段引用 |
| `ConnectionCondition` | 本播放项与相邻播放项的连接方式 |
| `RefToSTCID` | 引用的系统时钟序列 |
| `INTime` | 编排播放区间的起始呈现时间 |
| `OUTTime` | 编排播放区间的结束呈现时间 |
| `UOMaskTable` | 用户操作限制 |
| `StillMode` / `StillTime` | 静止画面行为 |
| `STNTable` | 本播放项对播放器公开的流 |

多角度播放项还包含其他片段标识和 STC 引用。根据标记，不同角度可能共用音频，也可能带有不同音频。

### `INTime` 与 `OUTTime`

MPLS 播放项时间使用 **45 kHz 时钟**：

```text
duration_seconds = (OUTTime - INTime) / 45,000
```

这些值是所引用 STC 序列中的时间戳，不是字节偏移，也不一定是从 M2TS 文件物理开头开始计算的秒数。

传输流通常使用 **90 kHz 时钟**表示 PTS、DTS 和 PCR base。基本换算为：

```text
mpls_timestamp_90k = mpls_timestamp_45k × 2
```

为了把播放列表边界换算成相对于 M2TS 第一条有效呈现时间戳的位置，BluraySubtitle 使用：

```text
start_seconds = (INTime × 2 - first_m2ts_pts) / 90,000
end_seconds   = start_seconds + (OUTTime - INTime) / 45,000
```

这说明为什么不能简单把 `INTime / 45,000` 当作相对于文件开头的跳转位置。M2TS 经常从非零传输时间线开始，播放列表也可能只选择文件中间的一个区间。

`OUTTime` 描述编排区间的结束边界。时间戳恰好等于该边界的访问单元是否包含在内，可能取决于流类型和抽流器语义。裁切视频、音频、PG 和 IG 的代码必须遵循具体工具的边界行为，不能假定所有流都采用同一个包含规则。

### STN 表

`STN` 表示 **Stream Number**。播放项的 `STNTable` 按类别描述播放列表公开的流，例如：

- 主视频；
- 主音频；
- 主 Presentation Graphics；
- 主 Interactive Graphics；
- 次音频；
- 次视频；
- 次 Presentation Graphics；
- Dolby Vision 或扩展定义的条目。

每个条目由两部分组成：

- `StreamEntry`：直接通过传输 PID，或通过子路径／子片段关系定位流；
- `StreamAttributes`：描述编码类型、视频格式／帧率、音频格式／采样率、语言等属性。

这一差异对 BluraySubtitle 很重要。PAT/PMT 解析可以发现物理存在于 M2TS 中的流，而 MPLS STN 表定义该播放路径编排为可见的流。被播放列表隐藏但物理存在的流不能自动当作已选择的标题内容。

### 播放列表标记与章节

`PlayListMark` 区域中的条目包含：

- `MarkType`；
- `RefToPlayItemID`；
- `MarkTimeStamp`；
- `EntryESPID`；
- `Duration`。

入口标记通常会成为章节。其时间戳属于所引用播放项的时间基准。要放到连续播放列表时间线上，需要计算：

```text
chapter_seconds =
    前面所有播放项时长之和
    + (MarkTimeStamp - referenced_item.INTime) / 45,000
```

标记是元数据，不是切点。章节表示导航位置。只有当相关流和容器能在该点干净起始时，通常即附近存在随机访问视频帧时，才可能在不重新编码的情况下精确切割。

## CLPI 二进制结构

CLPI 头包含以下区域的地址：

- `SequenceInfo`；
- `ProgramInfo`；
- `CPI`；
- 片段标记；
- 可选扩展数据。

### SequenceInfo

序列信息将片段划分为到达时钟序列和系统时钟序列。一个 STC 序列会记录：

- PCR PID；
- 起始 source-packet number；
- 呈现起始时间；
- 呈现结束时间。

MPLS 播放项的 `RefToSTCID` 指向相应 STC 序列。`INTime` 和 `OUTTime` 就是在这个时钟上下文中解释的。

### ProgramInfo

节目信息描述节目及其流，包括：

- Program Map PID；
- 流数量；
- 每条流的 PID；
- 编码类型、格式、采样率、语言等编码信息。

项目在修复或重建播放列表流表时会使用这些信息。

### CPI

**Characteristic Point Information** 索引将呈现时间映射到可用访问点的 source-packet number。播放器或抽流器可以利用它跳转到请求时间附近，而不必扫描整个 M2TS。

BluraySubtitle 当前的轻量 CLPI 解析器只读取序列信息和节目信息。高层工作流主要依赖播放列表窗口、传输时间戳、MKVToolNix 和定向恢复路径，并没有自行实现完整的 CLPI CPI 跳转模型。

## M2TS 二进制结构

蓝光 M2TS 基于 MPEG-2 Transport Stream，并在每个 188 字节 TS 数据包前增加四字节前缀：

```text
M2TS source packet：192 字节
├── TP_extra_header：4 字节
└── MPEG-2 TS packet：188 字节
    ├── 固定头
    ├── 可选 adaptation field
    └── 可选 payload
```

32 个 192 字节 source packet 组成一个 6,144 字节 aligned unit：

```text
32 × 192 = 6,144 字节 = 3 × 2,048 字节逻辑扇区
```

标准 TS 同步字节为 `0x47`，在普通 M2TS source packet 的第 4 字节偏移处。可据此检查对齐：

```text
偏移 4、196、388、580……处应为 0x47
```

BluraySubtitle 还会通过采样重复同步位置，识别普通 188 字节 TS 输入和少见的 192 字节布局。

### 传输包头

188 字节 TS 数据包头包括：

- 同步字节 `0x47`；
- transport-error indicator；
- payload-unit-start indicator（`PUSI`）；
- transport priority；
- 13 位 packet identifier（`PID`）；
- scrambling control；
- adaptation-field control；
- 4 位 continuity counter。

PID 标识数据包所属的逻辑流或表。continuity counter 有助于发现同一 PID 的数据包丢失、重复或乱序。adaptation field 可以携带 PCR 等时钟／控制信息。

### PAT 与 PMT

**Program Association Table** 位于 PID `0x0000`，负责把节目编号映射到相应 **Program Map Table** 的 PID。

PMT 随后列出：

- PCR PID；
- 基本流 PID；
- stream type 编码；
- 语言或注册信息等 descriptor。

PAT 和 PMT 区段可能跨越多个 TS 数据包。解析器必须处理 PUSI、pointer field、声明的 section length 以及多包组装。只扫描第一个 payload 片段并不可靠，尤其是 PMT 较大的 UHD 原盘。

### PES、PTS、DTS 与 PCR

视频、音频和图形基本数据通常先封装为 **Packetized Elementary Stream**，再拆分到多个 TS 数据包中。

- **PTS**：呈现单元应在何时展示或播放。
- **DTS**：当解码顺序和呈现顺序不同时，单元应在何时解码。
- **PCR**：提供用于同步解码器时钟的节目时钟基准。

PTS、DTS 和 PCR base 使用 90 kHz 单位。PCR 还包含更精细的 27 MHz extension，但项目计算片段时长时不需要它。

这些时间戳字段位数有限，因此会发生回绕。片段跨过回绕点时，时长代码必须使用模运算。

## 常见蓝光 stream type

以下编码值与项目关系最密切：

| 编码 | 流 |
| ---: | --- |
| `0x02` | MPEG-2 视频 |
| `0x1B` | AVC/H.264 视频 |
| `0x20` | MVC 依赖视频 |
| `0x24` | HEVC/H.265 视频 |
| `0xEA` | VC-1 视频 |
| `0x80` | 蓝光 LPCM |
| `0x81` | AC-3 |
| `0x82` | DTS core |
| `0x83` | TrueHD |
| `0x84` | E-AC-3 |
| `0x85` | DTS-HD High Resolution |
| `0x86` | DTS-HD Master Audio |
| `0x90` | Presentation Graphics（PGS） |
| `0x91` | Interactive Graphics（IGS） |
| `0x92` | Text Subtitle（TextST） |

descriptor 和蓝光扩展还可以进一步限定含义。仅凭 stream type 无法完整描述所有 Dolby Vision 或私有流变体。

## 为什么必须感知播放列表

### 文件内部时间窗口

如果某个播放项只选择一小时 M2TS 中的 10:00–20:00，直接拼接整个 M2TS 就会得到错误内容。抽流器必须在正确的 STC/PTS 时间基准中应用起止边界。

### 片段复用

一个 M2TS 可以出现在多个播放列表中，也可以在同一播放列表内重复出现。根据所选时间区间，同一批物理字节可能属于正片、SP，或同时服务于二者。

### 无缝分支

不同版本或剪辑可以共用大多数片段，只在分支处选择不同内容。应播放哪个版本由播放列表表达，而不是文件大小或文件名顺序。

### 轨道布局不同

相邻片段可能不具有完全相同的 PID。直接追加可能丢失轨道、改变轨道顺序或直接失败。BluraySubtitle 的回退流程会先把每个片段对齐到所选参考布局，再执行追加。

### 播放列表混淆

部分原盘包含大量片段顺序被有意打乱但看似合理的播放列表。此时“最长播放列表”只是很弱的启发式判断，可能必须实际播放检查或借助外部资料才能选择正确主 MPLS。

## 自动估算主播放列表的方式

BluraySubtitle 会综合多个因素，估算首次打开原盘时默认选中的主 MPLS。这只是方便用户开始检查的启发式方法，并不表示程序已经权威地确认了正确播放列表：

```text
评分 =
    去重后的播放列表时长
    ×（1 + 播放列表标记数 / 5）
    × MPLS 文件大小
    × 去重引用的 M2TS 文件总体积
```

同一个片段名称被重复引用时，在去重时长和 M2TS 体积两项中都只计算一次。

MPLS 文件大小之所以重要，是因为两条播放列表可能具有完全相同的片段列表和 `INTime`／`OUTTime` 窗口，但公开的轨道数量不同。这种情况会出现在一些容量较大的电影原盘中。STN 表更完整的播放列表通常才是需要的版本，而它往往也是体积更大的 MPLS。文件大小只是播放列表元数据和轨道条目数量的近似指标，最终仍应人工检查轨道。

最后一项是先把所有**不同的**引用 M2TS 文件体积相加，再将这个总量乘入评分；并不是把各个文件的体积彼此连乘。这样可以避免菜单类播放列表仅仅因为反复引用同一个小 M2TS，就显得比正片更重要。如果只累计重复时长而不考虑实际涉及的不同流数据量，就很容易把这类播放列表判成主 MPLS。

部分电影原盘会包含多条时长相同、引用文件不同、但实际观看几乎没有差异的播放列表，迪士尼发行的原盘尤其常见。BluraySubtitle 不会解码后逐一比较这些变体。候选评分完全相同时，程序只有遇到严格更高的评分才会替换当前选择，因此会保留最先枚举到的一条。这里依据的是目录枚举顺序，并不保证等同于 MPLS 数字文件名顺序。如果语言、本地化片段、分支或版本差异很重要，应手动选择。

## 剧集盘布局与按 MPLS 切割

以下名称是社区术语，并非蓝光规范定义的正式盘型。

### 连体盘

连体盘主要指多个剧集连续存放在同一个大 M2TS 中的原盘。主播放列表通过该文件内部的时间窗口选择内容，分集边界可能来自播放列表标记，也可能来自派生出的文件／时间边界。如果把整个 M2TS 当作一集，就会错误地把整卷内容合并到一起。

### 肉酱盘

肉酱盘主要指一集由多个 M2TS 拼成的原盘。复杂肉酱盘中的片段和章节并不是一一对应：有些 M2TS 上没有播放列表标记，有些 M2TS 上则有多个标记。因此，“一个 M2TS 等于一集”和“一个标记对应一个 M2TS”都不是可靠规则。

BluraySubtitle 依靠按 MPLS 切割的模型处理这两种布局。程序使用有序播放项窗口以及由章节／文件边界派生出的连续时间线，再从这条播放列表时间线上建立分集区间，不要求物理 M2TS 文件布局与剧集边界一致。

### 一条总播放列表与一集一条播放列表

动漫原盘通常由一条主 MPLS 串联所有剧集。少数原盘则是一集对应一条 MPLS，需要观众在原盘界面中逐集选择；这种布局在美剧原盘中更常见。BluraySubtitle 允许一卷原盘选择多条主 MPLS，此时应选中各集播放列表，并按期望的处理顺序排列。

### 末尾的短版权片段

许多动漫播放列表会在每集之后放置一段独立的版权信息 M2TS，时长通常只有数秒，移除它一般不会影响剧集内容。**查看章节**窗口和分集选择器仍然使用原盘编写的章节标记，因此位于两个标记之间的文件边界不能通过修改章节数据来隔离。

为此，剧集模式的重混流和压制工作流提供了**裁剪版权片段**选项。程序会分别检查每一个可见分集；只有原盘分集结束点与当前播放项的 CLPI 呈现结尾一致，即该范围确实到达底层 M2TS 文件结尾时，才会尝试裁剪。程序随后从该集结束点向前检查 30 秒，删除完整落在此窗口内且连续位于末尾的 M2TS 播放项，并把 `--split parts` 的结束时间推到删除后最后一个 M2TS 的结尾。这个规则既能处理每集之后都插入短版权文件的总播放列表，也能处理末尾由多个连续短文件组成的情况。

源 MPLS、`Chapter.in_out_time`、章节标记、**查看章节**以及其他章节计算均保持不变；程序只会从 table2 的 **m2ts 文件**列移除受影响的文件名，调整后的 parts 区间则体现在可见混流命令中。table1 会在**章节**列后提供 **M2TS 时间**入口，用于查看每个播放项的 `INTime`、`OUTTime`、CLPI 文件范围以及播放项是否结束于文件结尾。

这种处理是结构推断，可能误删合法的短内容。特殊原盘应检查 M2TS 时间和生成的命令；如果自动边界不正确，应关闭此选项，或者手动修改可见混流命令并指定已经确认的 `--split parts:start-end` 区间。如果版权画面嵌在较长播放项内部，最后 30 秒内不存在完整 M2TS 边界，程序仍然无法自动移除。

《境界线上的地平线》第一季原盘是这一特殊情况的代表。第一卷没有串联各集的单一总播放列表，而是包含多条单集播放列表；其中两条播放列表复用 `00004.m2ts`，但时长不同，因此 `m2ts_detail` 也不同。其他各卷的部分 SP 或评论音轨播放列表也与正片内容重叠，却使用不同的有效源时间窗口；其版权提示位于较长播放项窗口内部，并非独立的末尾播放项。因此，这些条目既不能自动把评论音轨附加到正片，也不能自动裁剪版权片段，需要人工检查 MPLS 选择的轨道以及准确的 `INTime`/`OUTTime`。

## 本项目中的正片与 SP

蓝光规范并未定义本项目使用的“主 MPLS”和“SP”。BluraySubtitle 在原盘结构之上建立以下内容模型：

- **主 MPLS** 是所选的正片、电影主体或剧集主体播放列表；
- 其中所选章节／片段范围形成主输出；
- 主播放列表中未勾选的范围成为 SP 候选；
- 其他播放列表成为 SP 候选；
- 未被任何播放列表覆盖、但能够确定性处理的 M2TS 也可以进入 SP 表。

因此：

```text
原盘内容
├── 所选主播放列表区间 → 主输出
└── 其余有用的编排内容或未覆盖内容 → SP
```

SP 可以包括普通视频特典、菜单、纯音频内容、纯字幕内容、IGS 资源和单帧图片，并不对应某一种编解码格式或容器。

### SP 轨道和被 MPLS 隐藏的轨道

M2TS 或 CLPI 可以声明比 MPLS Stream Number Table 实际允许播放的轨道更多。因此，PotPlayer、mpv、eac3to 和 mkvmerge 可能列出两条音轨，而 BluraySubtitle 只显示 MPLS 暴露的一条。PowerDVD 可以作为原盘制作行为的参考：被 MPLS 隐藏的轨道不会出现在正常标题播放中。

BluraySubtitle 不会盲目丢弃可能有用的内容。在剧集模式下，程序维护内部 `m2ts_detail`，其中包含每个 M2TS 名称及其有效源时间窗口。如果某个 SP 条目的 `m2ts_detail` 与唯一确定的一条主分集完全一致，该 SP 会关联到计划的分集输出；当它提供新的音频或字幕 PID 时默认勾选。SP 中已选择、但分集中尚未存在的音频或字幕 PID 会附加到对应 MKV；已经存在的 PID 不会重复添加。多个已选 SP 行提供同一 PID 时，以界面顺序中的第一行为准；所有附加的 SP PID 在原正片轨道之后保持升序。

这里要求的是完全一致，而不是时长近似相同。仅仅复用同一个 M2TS 并不充分；只要播放列表的 `INTime`、`OUTTime` 或片段顺序不同，就不会建立关联。在这种情况下——包括上文《境界线上的地平线》原盘——评论音轨条目会继续作为 SP，不会自动附加到正片。电影模式不存在 SP 附加正片的路径，SP 行始终作为独立输出处理。

其他不包含额外轨道的正片保持不变。通常，这种未暴露轨道是静音或重复音频。即使它实际包含非静音数据，只要正常 MPLS 播放无法选择它，并且没有时间线匹配的 SP 将它暴露出来，就不视为有效标题音频。

## 播放列表确认清单

判断某个 MPLS 是否属于主内容时：

1. 实际播放或检查播放列表，不要只看文件名。
2. 检查有序片段列表及每个 `INTime`/`OUTTime` 窗口。
3. 将时长与预期电影或剧集时长比较。
4. 检查章节和分支点。
5. 确认 STN 表公开的视频、音频和字幕流。
6. 查找重复或顺序被打乱的播放列表。
7. 检查其中是否包含应取消勾选并作为 SP 处理的片头、警告、菜单或无关内容。
8. 确认没有把多个合法主播放列表错误压缩成“每卷只能选一个”的假设。
